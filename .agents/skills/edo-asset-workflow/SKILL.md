# Kage no Machi 3D Asset Workflow (Midjourney -> Tripo MCP -> Blender -> flutter_scene)

All asset specs live in `tools/asset_pipeline/catalog.json`, run state lives in `tools/asset_pipeline/state.json`, and all CLI operations run through `tools/asset_pipeline/pipeline.py`.

## Guardrails

- Never store signed `upload_url`, `download_url`, `model_url`, or `required_headers` in `state.json`, logs, or git. Use `pipeline.py upload-grant` and `pipeline.py download-glb` (they read signed data on stdin and pass it to `curl --config -`).
- Never call Tripo write tools until the user authorizes the asset batch or pilot run. Report documented Tripo credit figures only as reference estimates, never as live account balances.
- Work in one serial task per concurrency slot (1–2 Tripo tasks at a time); always pass a stable `idempotency_key` generated by `pipeline.py plan-tripo`.

## Stage 0: Generate High-Quality Midjourney References

1. Inspect prompts and local reference status:
   ```sh
   python3 tools/asset_pipeline/pipeline.py prompts <asset_id>
   ```
2. Generate clean, isolated, evenly lit reference sheets in Midjourney using Helium:
   - Route 1: `browse` MCP (`tabs` -> reuse or open tab `id: "midjourney"` at `https://www.midjourney.com/imagine`).
   - Route 2: `cua-driver` on Helium if `browse` is offline.
   - Use `--sref` pointing to canonical Style B references (`docs/references/midjourney/tactical_shukuba_1.png` or `tactical_minato_1.png`) when style-locking.
   - Keep characters in a neutral A-pose (arms away from torso, feet apart, uncropped) on a plain neutral light-grey backdrop so Tripo auto-rigging succeeds.
   - For peekable houses (`machiya`, `minka`, `chaya`, `kura`), generate both the clean isolated exterior reference and the cutaway interior reference.
3. Save images under `docs/references/midjourney/assets/<asset_id>/` as `front.png` (and optional `left.png`, `right.png`, `back.png`, `interior.png`).
4. Optional 4-view expansion from one Midjourney image: call `tripo_generate_multiview_images`, then download each view via `tripo_get_image_asset` and re-upload via `tripo_create_image_upload_grant` + `pipeline.py upload-grant` before calling `tripo_multiview_to_model`.
5. Record completion:
   ```sh
   python3 tools/asset_pipeline/pipeline.py record <asset_id> --stage 0 --status done
   ```

## Stage 1: Build Model in Tripo MCP (HD v3.1 vs Smart Mesh P2)

1. Emit exact schema-validated JSON payloads:
   ```sh
   python3 tools/asset_pipeline/pipeline.py plan-tripo <asset_id> --stage 1
   ```
   Pass `--prefer-smart-mesh` to switch an HD building/landmark to Smart Mesh P2 (`Nexus-v2.0-20260801`).
2. **Choosing Smart Mesh P2 vs HD v3.1:**
   - **Smart Mesh P2 (`family: "smart_mesh"`, `model_version: "Nexus-v2.0-20260801"`)**: Use for **people, carts, boats, everyday props, interior furniture, and modular walls**. Gives clean quad topology (`quad: true`), optional `symmetry: true`, and predictable game poly counts (`face_limit: 4000`–`20000` — always pass `face_limit` explicitly; omitting defaults to 500!).
   - **HD v3.1 (`family: "hd"`, `model_version: "v3.1-20260211"`)**: Use for **ornate curved-eave houses, castles, bridges, pagodas, and hero ships**, especially with `geometry_quality: "detailed"`, `texture: false`, `generate_parts: true`, `segmentation_granularity: "balanced"` (or `"detailed"`).
3. **Upload local Midjourney image(s):**
   - Call `tripo_create_image_upload_grant(content_type="image/png", size_bytes=<exact bytes>)`.
   - Pipe the grant JSON into `python3 tools/asset_pipeline/pipeline.py upload-grant <local_file>` to receive `object_key`.
4. Submit `tripo_multiview_to_model` or `tripo_image_to_model`, poll `tripo_get_model_task` to terminal success, and record `model_id` with `pipeline.py record <asset_id> --stage 1 --model-id <uuid>`.
5. Never pass `pbr`, `texture_quality`, or `delight` when `texture: false`. Never pass `symmetry` for HD or Nexus v1.

## Stage 2: Componentize Appropriate Pieces

- **Characters (rigged):** Skip segmentation (`tripo_rig_model` requires a whole unsegmented model).
- **Houses, castles, carts, ships, multi-material lanterns:**
  - If Stage 1 used `generate_parts: true`, call `tripo_get_model_asset(model_id)` to read `parts_known` and authoritative `part_names`.
  - Otherwise call `tripo_segment_model(source_model_id=..., segmentation_granularity="balanced"|"simple", idempotency_key=...)`, then read `tripo_get_model_asset`.
  - For peekable houses whose roofs/upper floors detach cleanly, optionally run `tripo_complete_model` on the roof and wall parts so the hidden undersides and wall tops are closed.
  - If an HD segmented mesh is too dense for real-time Metal/Web, run `tripo_smart_low_poly_model` (`face_limit: 12000`–`20000`, `do_bake: true`, authoritative `part_names`).
- Record `part_names` and the resulting `model_id` in `state.json`.

## Stage 3: Texture & Upscale vs Custom Texturing (Visual Gate)

Choose between **Path A (Tripo)** and **Path B (Custom Blender Gouache)** after inspecting a quick preview sheet:

- **Path A — Tripo Texture (+ Optional Upscale & PBR):**
  1. Call `tripo_texture_model` with `delight: true`, `texture_quality: "standard"` (2K) or `"detailed"` (4K), and your uploaded Midjourney `image_key` or `images`.
  2. Optionally call `tripo_texture_upscale(texture_quality="detailed"|"extreme")` and `tripo_generate_pbr`.
  3. Inspect `tripo_get_model_asset(model_id)` for `model_url` (do not call `tripo_export_model` just to get a GLB!), pipe `model_url` into:
     ```sh
     python3 tools/asset_pipeline/pipeline.py download-glb tools/asset_pipeline/work/<asset_id>/raw.glb --decode-meshopt
     ```
  4. Render a 4-corner (+ cutaway) preview sheet:
     ```sh
     python3 tools/asset_pipeline/pipeline.py postprocess <asset_id> \
       --input tools/asset_pipeline/work/<asset_id>/raw.glb \
       --texture-strategy tripo_keep --render-preview
     ```
  5. Inspect `tools/asset_pipeline/work/<asset_id>/preview_sheet.png`.
- **Path B — Custom Texturing (When Tripo textures look muddy, shiny, or off-palette):**
  - Use `--texture-strategy tripo_hybrid` to keep sculpted Tripo textures on hero parts while binding Kage no Machi emissives (`ShojiGlow`, `ChochinGlow`, `LanternGlow`) and seamless gouache PBR (`KawaraTile`, `IshigakiStone`) to structural/interior parts.
  - Or use `--texture-strategy blender_gouache` (optionally after `tripo_uv_unwrap`) to texture cleanly with Kage no Machi's seamless Midjourney gouache PBR material library (`tools/blender/common.py`).

## Stage 4: Rig (People & Articulated Characters)

1. Run `tripo_rig_model(source_model_id=<textured whole model_id>, topology="biped", idempotency_key=...)` (omit `spec` to use Tripo's default skeleton for reliable preset retargeting).
2. Poll `tripo_get_model_task` to terminal success and record `--rigged-model-id <uuid>`.

## Stage 5: Assign Animations & Merge Clips

1. Look up live presets with `tripo_list_motion_presets(topology="biped")` (e.g., `preset:biped:wait`, `preset:biped:walk`), or author bespoke motion via `tripo_text_to_motion` -> `tripo_get_motion_asset(task.motion_id)`.
2. Call `tripo_retarget_model` once per clip (`idle`, `walk`, etc.) against `rigged_model_id`, and download each clip GLB.
3. Merge all clips onto the single primary Armature in Blender:
   ```sh
   python3 tools/asset_pipeline/pipeline.py postprocess <asset_id> \
     --input tools/asset_pipeline/work/<asset_id>/idle.glb \
     --extra-clips walk=tools/asset_pipeline/work/<asset_id>/walk.glb \
     --texture-strategy tripo_keep --render-preview --install
   ```
   `EdoWorldDriver` automatically binds `idle` and `walk` clips via `Node.parsedAnimations` + `Node.createAnimationClip` and cross-fades them by walking speed.

## Cutaway House Peeking Contract

Every peekable building GLB (`machiya`, `minka`, `chaya`, `kura`) MUST expose these node name prefixes:
- `peek_roof*` / `peek_upper*`: Exterior roof and upper-story cutaway meshes (visible when closed, hidden when peeking; `shadowStatic = false`).
- `interior_room*`: Recessed floor, tatami mats, and interior plaster walls strictly inset `>= 0.05 m` inside hollow exterior walls (`visible = false` when closed, `true` when peeking; `shadowStatic = false`).
- `interior_props*`: Archetype furnishings (`irori` hearth, `chabudai`, `tansu`, shop counter, sake casks, `andon` floor lamp; `visible = false` when closed, `true` when peeking; `shadowStatic = false`).
- `exterior_*`: Foundation skirt, hollow lower walls, framing, awnings, and exterior lanterns (always visible; `shadowStatic = true`).

Verify any building or character GLB before installing:
```sh
python3 tools/asset_pipeline/pipeline.py verify-glb assets/models/<file>.glb --asset-id <asset_id>
```

## Mandatory Final Verification

1. Run `python3 -m unittest discover -s tools/asset_pipeline -p 'test_*.py' -v`.
2. Run `flutter analyze` and `flutter test`.
3. Run macOS Metal captures and confirm `coplanarOverlapCount == 0` and `depthConflictCount == 0` across all presets including `interior_peek_closeup`:
   ```sh
   flutter run -d macos --enable-flutter-gpu \
     --dart-define=SHUKUBA_CAPTURE_DIR=/tmp/shukuba_cap \
     --dart-define=SHUKUBA_AUTO_EXIT=true
   ```
4. Visually inspect the rendered PNGs (closed overview + `interior_peek_closeup.png`) against `docs/references/shadow-tactics/` and `docs/references/midjourney/`.
